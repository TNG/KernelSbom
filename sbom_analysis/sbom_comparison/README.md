# SBOM Comparison (`sbom-compare`)

Semantic comparison of the SPDX 3.0.1 SBOM documents generated by the kernel
[`sbom` tool](../../sbom/) (`sbom-output.spdx.json`, `sbom-build.spdx.json`,
`sbom-source.spdx.json`).

The primary use case is validating a change to the sbom tool (e.g. a patch
series to the `.cmd` file parsing) by building the same kernel configuration
and comparing the resulting SBOM documents: the **reference** documents,
generated with the unmodified tool, and the **candidate** documents, generated
with the patched tool.

This tool is **fully standalone**: it imports nothing from the rest of the repository. In particular it does not import the `sbom` package.

## Why a plain diff is not useful

A raw `diff` of two SPDX documents is dominated by noise:

1. **Document-local identifiers**: every element carries an `spdxId` such as
   `b:123`, and `Relationship` elements reference other elements through these
   IDs. The numbering follows graph-traversal order, so even a semantically
   tiny change renumbers most IDs and makes the diff explode.
2. **Content-derived UUIDs**: the document namespace UUID is computed from the
   serialized graph, so it changes whenever *anything* changes — without
   telling you *what* changed.
3. **Ordering**: element order in `@graph` and the order of `to` entries in
   relationships are not semantically meaningful.

## How the comparison works

- **Deterministic element IDs**: the generator numbers elements by traversal
  order (`b:123`, ...), so the same object can end up with different numbers.
  Every `spdxId` is therefore replaced by a deterministic identifier derived
  from the element's own content: a human-readable key where one exists (file
  path for `software_File`, command text for `build_Build`, ...),
  disambiguated with a short content hash otherwise. References (`from`,
  `to`, `buildId`, ...) are rewritten to the referenced element's
  deterministic identifier. Unchanged elements therefore keep identical IDs
  in both variants, while the JSON structure stays intact.
- **Filter unchanged**: elements whose normalized form is identical in the
  reference and the candidate are removed from the `@graph` of both documents. What remains is exactly the set of added, removed, and changed elements.
- **Report**: results are written as a self-contained HTML report rendering
  that single diff with git-style green/red highlighting, plus a
  machine-readable JSON report.

## Installation

Register the tool locally with [uv](https://docs.astral.sh/uv/) so the
`sbom-compare` command is available in every directory:

```bash
cd KernelSbom/sbom_analysis/sbom_comparison
uv tool install .
```

## Usage

The tool expects a comparison directory containing a `reference` and a
`candidate` folder, each holding the three SBOM documents generated by the
sbom tool:

```
path/to/comparison/
├── reference/
│   ├── sbom-output.spdx.json
│   ├── sbom-build.spdx.json
│   └── sbom-source.spdx.json
└── candidate/
    ├── sbom-output.spdx.json
    ├── sbom-build.spdx.json
    └── sbom-source.spdx.json
```

```bash
sbom-compare path/to/comparison
```
